## Commands

```bash
npm run dev       # Start dev server (localhost:4321)
npm run build     # Production build - always run after changes to verify no errors
npm run preview   # Preview the production build locally
```

Brand assets (logo, favicons, OG image) are generated by `scripts/brand/gen.py` - never edit them by hand (see `STYLE.md` → Brand).

Checks: `bun scripts/check-sanitize.ts` (blog + user-post HTML sanitizer). Scripts are Bun-only (no `node:` imports; `scripts/tsconfig.json` has Bun types). Otherwise there are no test or lint scripts. Use `npm run build` as the verification step - it runs TypeScript checks and Vite bundling. Build errors from ECONNREFUSED are expected (local API not running) and do not block deployment.

## Architecture

**Stack:** Astro 6 (server output) + React 19 (islands) + Tailwind CSS v4 + Cloudflare Pages.

**Backend:** Separate repo at `/Users/hafiz/Developments/hono-workers` - a Hono API on Cloudflare Workers with D1 (SQLite) - no KV (sessions and caches moved off it 2026-10-09 to cut write costs). The portfolio fetches from it at `PUBLIC_API_URL` (`.env`: `http://localhost:8787/api/v1`; production: `https://api.hafizbahtiar.com/api/v1` - same site as the frontend).

### Rendering model

The project uses SSR (`output: "server"`) via `@astrojs/cloudflare`. Pages that need to be pre-rendered at build time use `export const prerender = true`. This avoids build-time fetch errors (ECONNREFUSED) by deferring data fetching to request time for non-prerendered pages, while still allowing static generation for others.

### Data flow

`src/lib/*.ts` - service classes that extend `ApiClient` (in `src/lib/api-client.ts`). Each service maps to an API resource (family, projects, blog, experiences, etc.). The `ApiClient` handles token refresh (httpOnly `refresh_token` cookie + in-memory `_accessToken`). Public endpoints need no auth; admin endpoints require a Bearer token obtained via `AuthService`.

### Layouts

- `CoreLayout.astro` - root HTML shell (theme choice lives in the public Footer's system/light/dark switcher), injects theme-init script (reads `localStorage("theme")`, adds `.dark` to `<html>`), uses Astro `<ClientRouter>` for SPA transitions.
- `PublicLayout.astro` - wraps CoreLayout with `Navbar`, `Footer`, `Background`.
- `PrivateLayout.astro` - wraps CoreLayout with `AdminSidebar`, `AdminNavbar`. Follows the app theme (light/dark) like the public site - do **not** re-add a locked `dark` class; every admin class needs a light and a `dark:` variant.
- `ProjectLayout.astro` - thin wrapper for the projects listing page.
- `AccountLayout.astro` - the account area (`/login`, `/register`, `/account/*`): its own shell built on **shadcn/ui** components (React islands in `src/components/account/`), variants `auth` (full-width split: brand panel left, form right) and `app` (signed-in nav). Admin signs in separately at `/admin/login` (the original public-shell login page); `/admin/*` redirects there, `/account/*` to `/login`. Not the public gutters/hairlines. Colors stay gray/sky; shadcn token classes stay inside `src/components/shadcn/`.

### Dark mode

Tailwind v4 with `@custom-variant dark (&:where(.dark, .dark *))` in `src/styles/index.css`. The `.dark` class is toggled on `<html>` by the inline script in `CoreLayout`. Admin follows the same theme. One palette everywhere - gray ink, **sky** accent, `.btn-pill-*` on public pages and the `.admin-*` atoms (`index.css`) inside admin. No slate/blue/cyan. See `STYLE.md`.

### UI components (`src/components/ui/`)

Custom Astro components with their own inline `<script>` blocks that set up event listeners. Key pattern: each component calls a `setup*()` function on load and re-registers on `astro:page-load`. Components expose `window.setup*()` globals so pages can trigger re-init after dynamic content.

- `Dropdown.astro` - single-select. Hidden `<input type="hidden">` stores value. Items must have a `<span>` wrapping the label text (required by the change-listener that reads `querySelector("span")?.textContent`).
- `MultiDropdown.astro` - multi-select, stores JSON array in hidden input.
- `DatePicker.astro` - the date field: shows/accepts **dd/mm/yyyy** (Malaysian format; native `type="date"` follows the browser locale, so it isn't used), submits ISO `yyyy-mm-dd` from a hidden input carrying `id` + `name`, calendar popover in our `.field`/`.menu` style (shadcn Date Picker pattern, no React/date lib: month+year dropdowns, Isnin-first grid, keyboard, "Hari ini"/"Kosongkan", `min`/`max`). Label with `for={`${id}-text`}`. Code that sets the hidden input must dispatch `change`; its `disabled` is mirrored. Logic in `src/lib/date-my.ts` (check `bun scripts/check-date-my.ts`). Used by `/tarikh-hijri`, admin Experience (via `DateInput.astro`) and Blog forms; `FamilyTreeBuilder.tsx` (React) still uses a native date input.
- `DateInput.astro` - admin label + `DatePicker`.
- `Alert.astro` - static callout (shadcn Alert in our palette): `variant` info|warning|danger|success|neutral, optional `title`, body in the slot (links/paragraphs/lists styled), `role="note"` by default. Toasts stay in `AlertToast.astro`.
- `Disclaimer.astro` - the Showcase penafian on `Alert` (warning): `sources` (agency name + link; empty = computed on the device) + a page-specific line in the slot (ibadah / kecemasan 999 / kesihatan / kewangan). Every Showcase app page ends with one; the full text is `/penafian` (`src/pages/penafian.astro`, linked from each Disclaimer and the footer). Keep the two in step and bump its `UPDATED` date when the wording changes. Widgets carry a one-line version with a link; Paparan Masjid has it in Tetapan.
- `Select.tsx` - React equivalent of Dropdown for use inside React components.
- `map.tsx` - MapLibre primitives (Map, markers, popups, controls, routes, polygons, clusters); CARTO tiles, follows the site theme. Popups draw their own themed card (MapLibre's white frame is reset in `index.css`).
- `PointsMap.tsx` - reusable interactive map of labelled points from plain props (`points: MapPoint[]` - id, lat/lng, title, subtitle, detail, badge, markerClass): fits all points, click/Enter selects + flies + popup, zoom/locate/fullscreen controls. Optional `lines` (`[lng, lat][]` each, drawn with `MapRoute`, included in the fitted bounds). Select from outside with `window.dispatchEvent(new CustomEvent("points-map:focus", { detail: { id } }))`. Mount with `client:only="react"` inside a fixed-height parent. Used by `/ipu`.
- `Combobox.astro` - searchable select for long lists (optional groups, search box, ↑ ↓ Enter Esc), same `.field-trigger`/`.menu` look. The native `<select>` keeps the value (no-JS fallback); on pick it fires `change`, or submits the form with `submitOnPick`. Per-option `data` goes onto the native `<option>`. Used by Waktu Solat (zones) and Kadar Tukaran (currencies).

### Public family pages (`src/pages/family/`)

`family/index.astro` and `family/[slug]/index.astro` use `prerender = false` and fetch public family data at request time through `src/lib/family.ts`. Public family fetches intentionally avoid `noCache` query params and avoid the shared no-store `ApiClient` path so the backend's in-isolate/HTTP cache remains effective.

`/family` builds the combined view server-side via `src/lib/family-merge.ts` and `src/data/family.ts`. Keep `/family` unlisted from the public navbar unless the privacy decision changes.

Before public family data is passed to React islands, `src/lib/family-privacy.ts` maps backend data into a strict public DTO. It strips notes, metadata, timestamps, tree IDs, relationship IDs, relationship dates, and admin/backend fields, and sanitizes living-person birth dates to year-only strings so full living birth dates are not serialized to the browser.

### Showcase (`src/pages/showcase.astro`)

**Data sources: Malaysian first, then fallbacks.** Every app fetches through `src/lib/fallback.ts` (`withFallback(key, [planA, planB, …])`): plans are tried in order, the answer is colo-cached ("fresh"), and a longer-lived "stale" copy is served - flagged `stale: true` - when every plan fails. Pages show which source answered and say when it is the stored copy. Check: `bun scripts/check-fallback.ts`. Current chains: Harga Minyak data.gov.my API -> data.gov.my CSV (static storage) -> stored; Waktu Solat JAKIM e-solat -> api.waktusolat.app (JAKIM mirror) -> stored; Kadar Tukaran BNM -> Frankfurter (ECB) -> open.er-api.com (needs the "Rates By Exchange Rate API" link) -> stored; Kiraan Detik JAKIM takwim -> stored -> Intl Umm al-Qura estimate; Peringatan source -> stored; IPU JAS APIMS -> stored (6 h only - no second real-time source).

Small public apps hosted on the site, each under its own route, listed in the `apps` array on `/showcase` (prerendered). Linked from the footer only for now - add a navbar/home section once there are enough apps. Adding an app: build its route, add one `apps` entry, end the page with a `Disclaimer` (and list its sources on `/penafian`).

- **Waktu Solat** (`src/pages/waktu-solat/`): today's prayer times per JAKIM zone. Data from JAKIM e-solat (`src/lib/waktu-solat.ts`: one `period=month` request per zone, colo-cached 6h keyed by zone + Malaysian month; bad responses are never cached). The same cached month also gives the kiblat bearing (shown on both pages) and the monthly table on `/waktu-solat` ("Cetak jadual" prints just the table from its own small window - no site-wide print CSS). "Guna lokasi saya" maps GPS to a zone via `api.waktusolat.app/zones/{lat}/{lng}` (JAKIM has no coordinate lookup); that host is in the CSP `connect-src`, and `Permissions-Policy` allows `geolocation=(self)` for it. Zones are static (`src/data/solat-zones.ts`, 60 JAKIM codes); `?zone=` is validated against that list (`resolveZone`) before reaching the upstream URL. `/waktu-solat/paparan` is the mosque display (Paparan Masjid) for screens in a mosque: own shell (no navbar/footer), sized by a `--u` unit (fits any landscape screen; phones/tablets held upright get a stacked, scrollable layout via `portrait:`), clock + countdown run on server time (screen boxes often have wrong clocks), reloads after Malaysian midnight, full screen + Wake Lock button. Its "Tetapan" dialog (nama masjid, pengumuman - a notice that takes over the centre for 10 s after every 20 s of clock, never within 2 min of azan or during iqamah/its banner, max 200 chars - zon, 12/24 jam, saat, angka Rumi/Arab, nama waktu Rumi/Jawi, tema gelap/terang, iqamah minit, peringatan, Mod Ramadan) is a plain GET form: settings live in the URL so a mosque bookmarks one URL per screen; every param is allow-listed in the page frontmatter. Background photos (Tetapan -> Latar, one for landscape/TV, one for portrait/phone; default `masjid-nabawi`, `latar=tiada` = none, `latar=gilir` = every photo in turn, one a minute; photos sit in two layers behind the content and fade in only after `decode()`, which also makes browsers repaint the cards' backdrop blur) are generated by `scripts/waktu-solat/backgrounds.py` (centre-crop to 1920x1080 / 1080x1920 WebP, optional focus point, skips an orientation that would need upscaling) into `public/images/waktu-solat/bg/` + `src/data/paparan-backgrounds.ts` - never edit those by hand; originals stay out of the repo. Both pages show a daily "Peringatan" (`src/lib/peringatan.ts`): even days an ayat (alquran.cloud, Uthmani + Basmeih `ms.basmeih`), odd days a hadis (HadeethEnc, Malay, with grade + Arabic attribution). Only references live in the repo (`src/data/peringatan.ts`, curated - no random verses on a mosque screen); text is fetched and colo-cached a week, and the page renders without it if a source is down.

- **Kadar Tukaran** (`src/pages/kadar-tukaran.astro`): Bank Negara Malaysia open API (`src/lib/kadar-tukaran.ts`, header `Accept: application/vnd.BNM.API.v1+json`), all ~27 currencies in one request, colo-cached 30 min. - **Kiraan Detik** (`src/pages/kiraan-detik.astro`): days to Ramadan, Aidilfitri, Aidiladha, etc. (`src/lib/hari-kebesaran.ts`). JAKIM publishes next year's takwim late in the year. Offline check: `bun scripts/check-hari-kebesaran.ts`.
